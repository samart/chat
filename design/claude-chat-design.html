01Interaction paths

Use the Agent SDK in the plugin host. It is exactly what the official extension does, and it handles framing, request ids, the initialize handshake and approvals for you. Drop to the raw protocol only if your host is not Node.

A · RECOMMENDED

Agent SDK query()

TypeScript package @anthropic-ai/claude-agent-sdk (a Python SDK also exists). Spawns the CLI you point it at, returns an async iterator of messages plus methods such as interrupt() and setModel().

B · ANY LANGUAGE

Raw stream-json

Spawn claude yourself and speak NDJSON on stdin/stdout. Needed for a JVM (JetBrains) or Rust host. You implement the handshake, control routing and approvals.

C · COMPLEMENT

Terminal attach

The user runs claude in the integrated terminal; it connects back to your editor's MCP server over a local WebSocket for diffs and diagnostics. No chat panel; the terminal is the UI.

Path A · plugin host (TypeScript)
import { query, createSdkMcpServer } from "@anthropic-ai/claude-agent-sdk";

const input = new PushQueue<SDKUserMessage>();     // async iterable you push user turns into

const q = query({
  prompt: input,
  options: {
    pathToClaudeCodeExecutable: managedCliPath,      // you manage the CLI
    cwd: workspaceRoot,
    resume: sessionId,                               // omit for a new chat
    model, permissionMode: "default",
    includePartialMessages: true,                    // stream_event token deltas
    enableFileCheckpointing: true,                   // needed for rewind_files
    settingSources: trusted ? ["user", "project", "local"] : ["user"],
    systemPrompt: { type: "preset", preset: "claude_code" },
    canUseTool: (toolName, input, { signal, suggestions }) =>
      approvals.ask({ toolName, input, suggestions, signal }),   // resolves allow / deny
    mcpServers: { ide: createSdkMcpServer({ name: "ide", tools: editorTools }) },
    hooks: { PreToolUse: [{ matcher: "Edit|Write|MultiEdit", hooks: [captureBaseline] }] },
    env: { ...cleanEnv(), CLAUDE_CODE_ENTRYPOINT: "my-editor" },
    stderr: (line) => log.debug(line),
  },
});

const caps = await q.supportedCommands();            // from the initialize response
for await (const msg of q) ui.post(msg);             // system / stream_event / assistant / user / result

input.push({ type: "user", message: { role: "user", content: "Fix the failing test" },
             parent_tool_use_id: null, session_id: "" });
await q.interrupt();                                 // Stop button
await q.setPermissionMode("acceptEdits");            // mode pill
await q.setModel("opus");                            // model picker
Path B · minimal raw host (Python, any language works)
proc = Popen([cli, "--output-format", "stream-json", "--input-format", "stream-json",
              "--verbose", "--permission-prompt-tool", "stdio", "--include-partial-messages"],
             stdin=PIPE, stdout=PIPE, cwd=workspace, env=clean_env, text=True, bufsize=1)

def send(obj): proc.stdin.write(json.dumps(obj) + "\n"); proc.stdin.flush()

rid = new_id()
send({"type": "control_request", "request_id": rid, "request": {"subtype": "initialize"}})
send({"type": "user", "message": {"role": "user", "content": "hi"},
      "parent_tool_use_id": None, "session_id": ""})

for line in proc.stdout:
    msg = json.loads(line)
    t = msg.get("type")
    if t == "control_request":                     # CLI needs us: approvals, MCP, hooks
        answer = route(msg["request"])           # can_use_tool -> {"behavior": "allow", "updatedInput": ...}
        send({"type": "control_response",
              "response": {"subtype": "success", "request_id": msg["request_id"], "response": answer}})
    elif t == "control_response":
        pending.pop(msg["response"]["request_id"]).resolve(msg["response"])
    elif t in ("keep_alive",):
        continue
    else:
        ui.post(msg)                             # unknown types too: tolerant reader

02Architecture

Only the protocol client touches the CLI's stdin and stdout. The webview renders; the host decides; the CLI owns the agent loop, tools, context, auth and transcripts.

flowchart TB
  subgraph EDITOR["Editor process"]
    W["Chat webview: transcript, composer, approval cards"]
    subgraph HOST["Plugin host"]
      PC["Protocol client: NDJSON, control router, tolerant reader"]
      AB["Approval broker: can_use_tool to card"]
      SM["Session manager: process per tab, resume, restart"]
      MCP["Editor MCP server: openDiff, getDiagnostics, selection"]
    end
    E["Editor APIs: diff tabs, diagnostics, files"]
  end
  CLI["claude CLI child process: agent loop, tools, permissions, auth"]
  J[("Session transcripts ~/.claude/projects")]
  API["Anthropic API"]
  W <-->|"typed postMessage"| AB
  W <-->|"typed postMessage"| SM
  AB --- PC
  SM --- PC
  MCP --- PC
  MCP <-->|"editor calls"| E
  PC <-->|"stdin / stdout NDJSON"| CLI
  CLI -->|"writes"| J
  SM -->|"reads history"| J
  CLI <-->|"HTTPS"| API

The webview never sees the CLI. Everything that reaches the CLI goes through the protocol client, so framing, request ids and unknown message types are handled in one place.

03Process lifecycle

One chat tab owns one long-lived CLI process and one session id. The process outlives turns; a crash is recovered by respawning with --resume, so no history is lost.

stateDiagram-v2
  [*] --> Discovering
  Discovering --> Unavailable: binary missing or below min version
  Discovering --> Spawning
  Spawning --> Initializing: process started
  Initializing --> Ready: initialize response
  Initializing --> Crashed: timeout or exit
  Ready --> Running: user message written
  Running --> AwaitingApproval: can_use_tool
  AwaitingApproval --> Running: control_response
  Running --> Interrupting: interrupt
  Interrupting --> Ready: result
  Running --> Ready: result
  Running --> Crashed: process exit
  Crashed --> Spawning: Restart with --resume
  Ready --> Closed: tab closed
  Closed --> [*]
PhaseWhat the host doesTimeouts and rules
DiscoveringConfigured path → managed install → claude on PATH; run --version once and cache.Refuse below the minimum supported version with a setup card.
SpawningBuild argv and env (section 04). Optional process wrapper prefix (ssh, docker exec).Strip inherited CLAUDECODE, CLAUDE_CODE_CHILD_SESSION, TRACEPARENT.
InitializingSend initialize first. Cache commands, models, agents, output styles, account, capabilities.30 s. Startup failure reason initialize_not_first exists in 2.1.325: nothing may precede it. Retry spawn once.
Ready / RunningWrite user turns; render stdout; answer control requests.A user message written mid-turn is queued by the CLI.
ClosedClose stdin, wait 5 s, SIGTERM, then SIGKILL.Never two processes on one session id.

08Permissions

The CLI decides whether a tool needs approval; the host only renders the question and returns the user's answer. Never auto-approve in the host: policy lives in CLI settings so the terminal and the panel behave the same.

flowchart TD
  T["Claude calls a tool"] --> P{"CLI rules and permission mode"}
  P -->|"allowed"| R["Tool runs"]
  P -->|"denied by rule"| X["Error returned to Claude"]
  P -->|"ask"| Q["control_request can_use_tool"]
  Q --> K["Approval card on the tool card"]
  K -->|"Allow"| A1["allow + updatedInput"]
  K -->|"Always allow ..."| A2["allow + updatedPermissions from suggestions"]
  K -->|"Deny with feedback"| D1["deny + message"]
  K -->|"Deny and stop"| D2["deny + interrupt true"]
  A1 --> R
  A2 --> R
  D1 --> X
  D2 --> S["Turn ends"]
ModeBehaviourLabel
defaultAsk for edits, shell, anything not allow-listedAsk before edits
acceptEditsEdits auto-approved; shell still asksEdit automatically
planRead-only; ends in an ExitPlanMode request showing the planPlan mode
bypassPermissionsNothing asks; hidden unless the user unlocks itBypass

Read the valid modes from the CLI rather than hard-coding them: 2.1.325 also has auto-mode settings, and a bad set_permission_mode returns the full list.

  • updatedInput is required on allow: the original input, or the user's edited version, with unknown keys kept.
  • Only send updatedPermissions taken from that request's permission_suggestions; drop a setMode: bypassPermissions suggestion unless the user unlocked bypass.
  • AskUserQuestion is answered with allow and updatedInput = input plus answers. ExitPlanMode approve = allow then set_permission_mode; keep planning = deny with feedback.
  • A control_cancel_request for a pending approval closes its card as "cancelled".
